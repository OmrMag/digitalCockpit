01

Overview

The Digital Construction Cockpit is an internal web application built at ALEC Holdings to manage users, run data extractions, and automate workflows across three construction platforms: Revizto Morta Forma / ACC

It has two layers that work together:

Web App Layer

A FastAPI web server (app.py) serves a browser UI. Users log in, select active projects from the sidebar, and trigger actions — invites, searches, extractions, settings — all through the browser.

Script Layer

Python scripts organised per platform handle all API calls. They read from config.json and write outputs to exports/. Scripts run both from VS Code (direct) and from the web app (via subprocess).

⚡ Single source of truth: config.json is the bridge between the web app and all scripts. Everything reads from it. The web app writes to it. Scripts never write to it — they only read.

Config System

config.json is the single file that connects everything. It has five top-level keys:

KeyWhat it storesWritten by
mortaAPI key, hub_idSettings page
revizto_dubaiaccess_code, default_license_roleSettings page
revizto_irelandaccess_code, default_license_roleSettings page
formaclient IDs, secrets, account_id, admin_user_id, selected modelSettings page + Extractions model selector
projectsCached project lists per platformSidebar refresh button
active_contextCurrently selected project per platformSidebar dropdowns
⚠ Note: license_uuid and auth_method for Revizto are not stored in config — they are resolved dynamically from the API at runtime via /user/licenses and /license/{uuid}/auth-methods. This is by design so users never need to enter them.

Each platform has its own Config.py file that reads from config.json at import time:

Revizto_Config.py

Resolves REGION from active_context, builds BASE_URL, reads ACCESS_CODE, sets TOKENS_FILE path, exposes PROJECT_UUID and PROJECT_NAME.

Morta_Config.py

Reads API_KEY from morta block. Reads HUB_ID from active_context.morta_hub_id first, falls back to morta.hub_id.

Forma_Config.py

Reads credentials from forma block. Reads PROJECT_ID from active_context.forma_project_id first. Exports _ROOT_DIR and EXPORTS_DIR for other modules.

Web App (app.py)

app.py is a single-file FastAPI application. It serves the browser UI and exposes a REST API consumed by the frontend JavaScript.

Route groupRoutesPurpose
Pages GET / /manage /extractions /scheduler /settings /invite /info Render Jinja2 HTML templates
Auth POST /api/auth/check-email /api/auth/login /api/auth/register GET /logout Session-based login. Domain restricted to @alec.ae

Projects GET /api/projects POST /api/projects/fetch Return cached projects or fetch fresh from each platform API

🔒 Every route (except auth routes) is protected by require_user — a dependency that checks the session cookie. If not logged in, the user is redirected to /login.

05

Platforms

Revizto Dubai (ME) · Ireland (EU)

API Base URL

https://api.{region}.revizto.com/v5

Auth Flow

One-time access code → OAuth2 token pair (access_token + refresh_token). Token saved to revizto_tokens_{region}.json. Refresh attempted first on every request; falls back to access code if refresh fails. Access codes expire after one use — generate a new one monthly at ws.revizto.com/login?request=accessCode.

License resolution

License UUID and Auth Method are never stored in config. They are fetched at runtime from GET /user/licenses and GET /license/{uuid}/auth-methods and cached in-memory per request.

Project resolution

Fetches all user licenses, then fetches projects per license, deduplicates by UUID. Handles multi-license accounts. Region comes from active_context.revizto_region.

Morta Single region

API Base URL

https://api.morta.io

Auth Flow

Simple Bearer token (API key). Stored as morta.api_key in config. No token refresh needed — keys are long-lived.

Hub resolution

Active hub ID read from active_context.morta_hub_id. Falls back to morta.hub_id in config. Hub list cached in projects.morta.

Email as identifier

Email is the universal key for user lookups. Morta_GET_User.py returns a dict keyed by lowercase email for O(1) lookups.

Forma / ACC Autodesk Platform Services

API Base URL

https://developer.api.autodesk.com

Auth — 2-legged

Client credentials flow (client_id + client_secret). Used for account-level operations. Token cached in forma_tokens.json with expiry check. Scopes: account:read account:write data:read.

Auth — 3-legged

Authorization code flow. Requires a browser session — run Forma_MasterScript.py directly from VS Code to cache the token. When running from the web app subprocess, falls back to 2-legged automatically. Token cached in forma_tokens_3l.json with refresh.

Project IDs

All Autodesk API calls require b. prefix on hub and project IDs (e.g. b.{account_id}, b.{project_id}). The prefix is added at call time — IDs are stored without it in config.

Model cache

BIM model lists are cached per project in forma_models_cache.json keyed by project_id. Selected model stored at project_id__selected. Fetch Models button forces a fresh walk of the folder tree.

Platforms within ACC

Projects can be on acc or bim360. Both are fetched and listed. The platform field is stored on each project in the cache.

08

Exports Folder

Every script writes its output to exports/ at the project root. This is the single folder you check after running any extraction. Files are overwritten on each run — they are not versioned.

📁 The web app serves these files at GET /api/exports/{filename} so the browser can read them (e.g. the Revizto model selector reads revizto_scenes_models.json after a Scenes & Models run to populate the L3 dropdown).

File naming follows the pattern {platform_prefix}_{resource}.{ext}:

revizto_*

user_licenses · license_projects · license_members · project_roles · project_members · clash_tests · scenes_models · object_tree

morta_*

admin · members · tags · invite_response

forma_*

account_projects · hub_users · project_files · project_models · projects_users · model_properties · model_elements · model_report

Auth & Tokens

Web App Login

Session-based auth using a signed cookie. Login flow is 2-stage: email check → password. First time users go through a register stage. Domain is restricted to @alec.ae. Passwords are hashed with bcrypt. User accounts stored in users.json.

Platform Token Summary

PlatformToken typeExpiryStored inRefresh
Revizto OAuth2 access + refresh Access: ~1hr · Refresh: ~1 month revizto_tokens_{region}.json Auto on every request. Falls back to access code if refresh fails.
Morta API Key (Bearer) Long-lived (no expiry) config.json → morta.api_key Not needed.
Forma 2L Client credentials ~1hr forma_tokens.json Auto — fetches new token when expired.
Forma 3L Auth code + refresh Access: ~1hr · Refresh: long forma_tokens_3l.json Auto refresh. Initial auth requires browser — run Forma_MasterScript.py from VS Code.
⚠ Revizto access codes are one-time use. Once you paste an access code into Settings and save, or the script uses it to get a token, the code is consumed. Generate a new one each time the refresh token expires (~monthly) at ws.revizto.com/login?request=accessCode.
10

Adding a New Script

Follow these steps to add a new extraction script and wire it up to the web app:

1
Create the script in the correct platform folder (codeRevizto/vsCode/, codeMorta/vsCode/, or codeForma/vsCode/). Name it {Platform}_{VERB}_{Resource}.py.
2
Import from the platform Config, not hardcoded values. Use PROJECT_UUID, EXPORTS_DIR, API_KEY etc. from the Config file. Guard the entry point with if not PROJECT_UUID: exit(1) for L2/L3 scripts.
3
Save all outputs to EXPORTS_DIR using os.path.join(EXPORTS_DIR, filename). Never save to CWD. Follow the naming convention {platform}_{resource}.csv.
4
Add a card to extractions.html. Copy an existing card and update data-script (must match the filename without .py), data-level (1, 2, or 3), data-platform, and the output filename in ext-output.
5
If the script name doesn't start with Revizto/Morta/Forma, add its prefix to PLATFORM_MAP in app.py so the extract endpoint can route it correctly.
6
Test from VS Code first, then test via the Extractions page. Check the server terminal for any errors — all scripts print [Platform] Status: 200 lines that help diagnose issues.
💡 Extraction levels: L1 = license/account level (no project needed), L2 = project level (requires active context), L3 = model level (requires project + model selection). Cards are automatically disabled/enabled by the Extractions page JS based on what's set in the sidebar.
